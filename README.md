支持**七类**论文类型，覆盖理、工、文、管、医各专业的本科与硕士论文写作，**每类走一条差异化的工作流**（见下文「按论文类型的差异化工序」）：设计字段**先于大纲**录入，成为大纲的已知条件；七类的文献与引用**均可显式跳过**；文献综述另有一道**主题聚类与人工确认**。**七类各有中、英两套骨架，同一类选中文还是英文都由选题步的「写作语言」决定**（见下文「写作语言」）。

| 短名（存库） | 长名（下拉框显示） |
| --- | --- |
| 定量/实证研究 | 定量/实证研究（社科、经管、医学、部分理科） |
| 质性研究/案例分析 | 质性研究/案例分析（人文社科、新闻、教育、公共管理） |
| 工程设计/系统实现 | 工程设计/系统实现（计算机、电子、机械、建筑等工科） |
| 理论推导/数理建模 | 理论推导/数理建模（数学、理论物理、理论经济学） |
| 文献综述 | 文献综述（全学科通用） |
| 课程论文/小论文 | 课程论文/小论文（全学科通用[短篇]） |
| 技术/工程报告 | 技术/工程报告（工科、实践类项目） |

短名是稳定标识（入库、接口、提示词、闸门判断都用它），长名只是下拉框里的文案，二者由 `paper_types.TYPE_LABELS` 连接。括号里的适用范围**不是数据的一部分**——把它写进库里，将来想改措辞就得动数据。

**七类长名一律带括号**（`文献综述（全学科通用）` 是后来补上的——它原先括号里的说明与短名重合，等于没有长名）。改长名只动一行文案、不碰数据；改短名则是迁移事件，两者成本差着量级，这正是当初把两者拆开的理由。

## 核心价值

| 价值 | 说明 |
| --- | --- |
| 0 幻觉引用 | 所有引文严格基于真实上传文档与页码 |
| 精准字数控制 | 从大纲层级锁定字数，解决长文本缩水 |
| 高确定性体验 | 两次关键人工确认点，长文生成全程可控 |
| 作者成果可入正文 | 作者自有的研究思路、数据与成果经模型分析后按节注入正文，与文献引用分轨管理 |
| 分析内容不靠编 | 设计字段（研究设计 / 质性设计 / 工程设计 / 理论模型 / 技术方案）**先于大纲**录入，成为大纲的已知条件；设计未覆盖之处标注「需作者补充」，而不是补一个看起来合理的假结果 |
| 工序随类型走 | 文献综述按文献定结构（含主题聚类）、实证研究按数据定结构、七类可整段跳过文献与引用——不是一套流水线套所有论文 |
| 结构不错位 | 七类各有自己的骨架、结构说明与写法要求：质性研究不会被套上「假设检验 / 变量与数据」，数学论文不会被套上「描述性统计」 |
| 正文按类型写 | 每节提示词携带**选题、类型名与该类型的写法要求**——只给「节标题 + 字数」，七类的正文写出来彼此没有区别 |
| 中英双语，界面不跟着翻 | 选题步可选**写作语言（中文 / 英文）**：它只管**会印进论文的那些字**——标题、摘要、关键词、骨架的章/节标题、正文、参考文献形态、导出排版；界面文案与工序名仍是中文。字数口径随语言切换（中文按字、英文按词），参考文献格式的可选项也随之收敛——**选了英文，下拉里就不会再出现 GB/T 7714** |
| 上游改动不静默 | 改选题 / 类型 / 写作语言 / 字数 / 写作思路会**覆盖式作废**下游产物（大纲、正文、绑定、材料计划），并在提交前逐项列明将失去什么、提醒先导出一份——不保留按旧选题写成的稿子，也不在用户不知情时删稿 |
| 回看不等于回退 | 步骤条可在已走过的步骤间**前后自由跳转**，回看不会作废任何东西，也不会让你以为后面的活被撤销了 |
| 标题就是研究核心方向 | 项目名即论文标题：没手动命名时**跟随选题**，可随时就地改名（清空即回到跟随），并一路进到导出成品的一级标题与下载文件名——不再有「未命名论文」 |
| 作者的话优先 | 选题步可以写下自己的**写作思路与论证思路**（选填，2000 字以内）：它进大纲第一遍、也进每一节正文；与模型自己的推断冲突时**以你写下的为准**——大纲的主线由你的思路收敛而来，而不是模型替你定 |
| 引用与正文对得上 | 生成完后改了文献或重做调度，界面挂一条**不可关闭**的告警条说明"绑定与正文不一致"，并在**生成前拒绝**（400）而不是静默改写你的正文；把绑定改回原样，告警条自己消失 |

## 按论文类型的差异化工序

工序表存放在 `backend/app/paper_types.py` 的 `TYPE_CONFIG`，是**单一事实来源**：前端步骤条由 `/api/meta` 下发渲染，后端闸门（谁必须先有文献、谁必须有引用绑定）从同一张表读取。二者各写一份，就会出现"前端让点、后端 400"。

| 论文类型（短名） | 设计步 | 工序 |
| --- | --- | --- |
| 文献综述 | — | 选题 → 文献注入 → **主题聚类确认** → 大纲 → 引用调度 → 生成 → 导出 |
| 定量/实证研究 | **实证设计** | 选题 → 设计 → 大纲 → 文献注入 → 引用调度 → 生成 → 导出 |
| 质性研究/案例分析 | **质性设计** | 选题 → 设计 → 大纲 → 文献注入 → 引用调度 → 生成 → 导出 |
| 工程设计/系统实现 | **工程设计** | 选题 → 设计 → 大纲 → 文献注入 → 引用调度 → 生成 → 导出 |
| 理论推导/数理建模 | **理论模型** | 选题 → 设计 → 大纲 → 文献注入 → 引用调度 → 生成 → 导出 |
| 课程论文/小论文 | — | 选题 → 大纲 → 文献注入 → 引用调度 → 生成 → 导出 |
| 技术/工程报告 | **技术方案** | 选题 → 设计 → 大纲 → 文献注入 → 引用调度 → 生成 → 导出 |

七类的**引用调度**步骤同形，跳过条件不同：文献综述在零文献时不允许跳过，其余六类可以。

**差异真正落在三处**，且都只写在 `TYPE_CONFIG` 这一张表里：

- **骨架**（`PAPER_TEMPLATES`）：每类的「章 → 节 → 权重」。章数与每章节数由骨架**定死**——模型只负责把通用占位标题改写成贴题的标题，结构永远赢、标题允许改写（按「章序号, 节序号」对齐），所以模型不会给自己加一章。
- **设计字段**（`design_label` / `design_fields`）：五类各有专属的四个字段，在大纲之前录入。
- **提示词**：`structure_note` 逐类写清「必须有哪类章节、绝不许出现哪类章节」（质性的访谈论文不该有假设检验，模型的常识里没有这条），进第一遍大纲提示词；`writing_note` 规定该类论文**该怎么写**，进正文提示词。

步骤条上「设计」那一步的标签取该类型的 `design_label`（实证设计 / 质性设计 / 工程设计 / 理论模型 / 技术方案），而不是统一写「研究设计」——否则有设计步的五类在步骤条上会显示成同一个词，而卡片标题又是类型专属的，两处对不上。类型下拉框下方的流程提示（`flow_hint`）同样随类型变化。

通用段（各类型共用）：

```
[人工确认点①] ← 大纲生成与字数分配
   ├── 轨一：文献下载指南 → 上传解析 PDF → 全局引用调度 → [人工确认点②] ─┐
   └── 轨二：作者自有材料 → 融入分析 ───────────────────────────────────┤
                                                                        └→ 渐进式分段生成 → 预览导出
```

两条轨可任选其一或同时使用。轨一经引用调度进文末参考文献列表；轨二不经调度，直接注入正文。

「毕业论文」已删除——它与「课程论文」的骨架和定位重复，类型数最终收敛为七类。类型解析对未知值一律退化为课程论文（`DEFAULT_TEMPLATE_KEY`），老数据不会崩。

旧类型名做**一次性显式迁移**（`PAPER_TYPE_RENAMES`，由 `db.init_db` 执行）：`实证研究 → 定量/实证研究`、`课程论文 → 课程论文/小论文`、`技术报告 → 技术/工程报告`，共 6 行。按**明确命名的键**逐条 `UPDATE ... WHERE paper_type = ?`，不枚举、不按模式匹配，跑第二次匹配 0 行、天然幂等。映射定义在 `paper_types.py` 而不是 `db.py`——「类型名有哪些」这件事只该有一个出处，db 只负责执行。不迁移的后果很实在：老项目会静默退化成课程论文，工序、设计字段与闸门全部变样。

### 设计先于大纲（五类）

大纲里的分析类章节——「实证分析」「资料分析与发现」「系统实现」「推导与证明」——要写的就是作者用的什么模型、访谈了谁、证明了什么、实测到什么结果。如果大纲环节只拿到「选题 + 类型名」，模型只能编——编变量、编编码、编证明。**用户在确认点①看到的是一份看着合理、实则虚构的大纲，而这份虚构会一路带进正文**（正文环节虽然能拿到作者自有材料，但大纲已经定死了写作要点）。

所以这五类论文在选题之后、大纲之前插入一步「设计」：

| 论文类型 | 步骤名 | 字段（固定四项，不可自由增删） |
| --- | --- | --- |
| 定量/实证研究 | 实证设计 | 数据源与样本、研究假设、模型与方法、主要结果 |
| 质性研究/案例分析 | 质性设计 | 研究对象与个案、质性方法、资料来源与编码、主题与发现 |
| 工程设计/系统实现 | 工程设计 | 需求分析、架构设计、功能实现、测试验证 |
| 理论推导/数理建模 | 理论模型 | 基本假设与公理、推导框架与符号、关键推导与证明、机制与结论 |
| 技术/工程报告 | 技术方案 | 项目背景与目标、技术选型与架构、关键参数、实测结果 |

文献综述的结构由文献与主题聚类决定（见下文），课程论文/小论文是短篇，二者不设设计步。

**字段名是数据的键**：改一个字段名，已存项目里那个字段的内容会静默变空。字段名一经发布即视为契约，调整需配套迁移。

- **两种录入方式**：手工逐项填写，或上传附件后由 AI 提炼成这四个字段（**提炼结果可逐字手改**）。
- **提炼附件与「作者自有材料」是同一份存储**：上传的文件直接进材料库，后续「融入分析 → 逐节注入正文」这条链路一行都不用改。设计步只负责把附件里的东西提炼成结构化字段，喂给大纲。
- **提炼严禁推测**：字段白名单校验（模型多吐的键一律丢弃），填不出来就留空并说明原因。推测出来的「主要结果」比空着更危险——它会被当成作者的真实结果写进第四章。
- **未填设计也能生成**：点击「生成大纲」时弹确认框说明后果（"分析章节可能编造数据"），**确认后照常生成，后端不硬拦**。护栏该拦退化，不该拦用户已被告知的明确选择。
- 设计字段进入大纲提示词时附三条硬规则：**分析类章节**（「分析」「结果」「检验」「测试」「验证」「推导」「证明」「编码」「实现」）只能依据上面给出的内容，严禁编造数据、变量与模型、显著性水平、访谈原话、定理或证明、性能指标或结论；设计未覆盖的部分在标题或备注里标明「需作者补充」，而不是补一个看起来合理的假结果；与设计冲突的既有文献结论不写进这些章节。

### 文献综述：主题聚类是显式产物，不是提示词里的一句话

文献综述的结构**由文献决定**——它的主题章就是文献之间的对话。若这一层只写在提示词里（"请归纳出 2–4 个主题维度"），用户既看不见模型据以定结构的依据，也无法在结构定死之前纠正它：等看到大纲时，主题已经变成章节了。

因此聚类做成一份**能看、能改、能确认**的中间产物（`projects.clusters_json`）：

- 输入是已解析的全部文献 + 选题，复用文献上下文的既有格式化，不另写一份。
- 簇数 2–6，簇标题 ≤ 60 字（与大纲标题同一把尺子）。
- **`doc_ids` 按库内实际文献做白名单校验**：模型编出来的 id 一律丢弃。这不是格式校验——聚类里出现一篇不存在的文献，就是一次引用幻觉的种子。
- **未归入任何簇的文献由服务端算出并逐条列明原因**，不采信模型自述。超过单次分析上限（30 篇）的文献也在此列明。
- 界面上簇标题可逐条改写、可查看每簇含哪些文献，确认后才写 `confirmed_at`。
- 确认是**非破坏性**的：已有大纲时返回 `outline_stale: true` 提示"建议重新生成大纲"，**不自动作废或重写既有大纲**——已经写过的东西不该被一个次级产物悄悄改掉。
- **不给硬闸**：未确认聚类就点「生成大纲」时弹确认框说明后果，与"设计未填"同款告警放行。

已确认的聚类只进入**第一遍**大纲提示词（结构那一遍），第二遍字数分配不带它——与设计字段同一规则。块内写明优先级：这些维度**已由作者逐条确认**，优先于模型自己的归纳，每一簇对应一个主题类章节，**不要另立一个不在其中的主题**；簇数与主题章能容纳的节数不一致时须显式说明怎么处理（多了合并、少了一起放进同一节），而不是擅自增删结构。该块**在无聚类时渲染为空串**，保证其余类型与未用聚类的文献综述的提示词逐字节不变；有聚类时它**取代**"自己归纳出 2–4 个主题维度"那句指令——两句并存只会让模型挑省事的那句执行。

### 设计字段为什么逐节全量下发，而不是按标题匹配

材料按章节标题精确投递（只进被分配到的那一节），设计**逐节全量下发**，这是刻意的不一致：字数分配那一遍会让模型改写章节标题，一旦关键词匹配失配，作者的数据就会**静默地**从正文里消失——而这正是本功能要解决的问题。代价是每节都会看到设计，因此提示词里配了使用规则：只在相关的地方用，不相关就不写，不要硬塞；需要作者补充的地方如实写成「此处需作者补充」。

### 跳过引用调度：七类全开，一条窄守卫

技术/工程报告的立身之本是技术方案与工程参数，不是参考文献：以前它被「请先上传文献」（引用调度）和「缺少引用绑定」（生成闸门）两道闸挡在门外，不得不为了跑通流程而硬凑几篇文献。现在不传文献时，该步直接提供「跳过引用调度」入口——**七类都有**：

- **跳过必须给后果明确的确认框**（不是一键静默跳过）："跳过 = 全文不产生参考文献列表、正文不出现引用角标。学位论文通常需要参考文献。确定跳过？"护栏拦的是退化，不是用户已被告知后果的明确选择。
- 「无引用」用**引用绑定缺省**表示，不引入哨兵值——生成环节对缺省绑定天然跳过，参考文献列表为空。
- 策略位 `citations_required` 保留不删（七类当前一律 `false`）：将来想收紧某一类，改一个字即可；删掉等于把策略散进代码。
- **一条窄守卫**：文献综述在**零文献**时调用跳过返回 400。这不是用户的选择而是结构性退化——它的骨架本就由文献聚类生成。零文献的文献综述在大纲步已被闸门拦住，这条守卫覆盖的是"生成大纲后把文献全删光"这条可达路径。
- 跳过后的正文约束随之切换：**不得出现角标、不得提及参考文献、不得编造文献观点**，需要佐证时用一般性的学术论述表达。这条约束在**该节没有绑定文献时自动生效**，不是用户在界面上勾的选项。

### 双轨资源注入：文献与作者自有材料是两条线

| | 轨一：文献（`documents` 表） | 轨二：作者自有材料（`materials` 表） |
| --- | --- | --- |
| 内容 | 上传的 PDF 文献 | 作者自己的研究思路、数据与成果 |
| 来源 | 批量上传 PDF | 上传文件（PDF/docx/xlsx/txt/md/csv/json/log）或直接粘贴文本；**研究设计步上传的附件也进这里** |
| 解析 | 后台任务，逐篇调 LLM 提取元数据，逐篇落库；**某一篇的提炼失败只算那一篇**（计入失败清单、继续下一篇），不会被吞成"解析成功、AI 没找到内容" | 纯本地文本提取，毫秒级，同步返回 |
| 下游 | 引用调度 → 角标 + 参考文献列表 | 融入分析 → 按节注入正文，**不加角标、不进参考文献** |
| 失败影响 | 单篇失败不影响整批，失败清单可补传；**全部失败不会报成成功**——那是"一篇都没进库却显示解析完成"，用户会以为文献已在库里；**部分页失败单独上报**（`partial`），不阻断入库但也不会被说成完全成功 | 单份失败不影响整批 |
| 删除后果 | 若已被引用：作废整份绑定、退回资源注入中 | 作废材料融入计划，需重新分析 |

两者**刻意分表**：`documents` 会被引用调度与参考文献列表消费，若把作者材料混进去，它们会作为"文献"出现在文末参考文献里——那是学术事故。

**文献轨按内容判重**：同一篇文献重复上传不会再变成两篇（此前全链路一处判重都没有，同一份 PDF 会占两个 doc_id——正文里两个角标指向同一篇、文末列表里两条内容相同却编号不同，删掉一条另一条还在）。判据是**内容**，不是文件名、更不是解析出来的题名（实测有反例：两份**不同**文件都解析成「Annual Report」，按题名判重会真丢文献）；判重限**同一项目内**（两篇不同论文引用同一篇文献是正常的）。命中就**跳过并点名**是哪几篇（`skipped`：文件名 + "与《…》内容相同"），**不整批拒绝**——一次传 10 篇有 1 篇是旧的，另外 9 篇照常入库；一批全是重复也报成功（库里本来就有这些文献，报红反而像上传挂了）。判重跑在**调模型取元数据之前**，重复的那一篇不白花一次 LLM 调用。判据打在**落库的内容形态**（每页页码 + 该页前 300 字）上，于是启动时的迁移能把改动之前传过的老文献反算出同一个指纹，重传老文献照样被认出来。

### 参考文献怎么著录：GB/T 7714-2015 / APA 7 / MLA 9，期刊为主

文末参考文献列表按 **GB/T 7714-2015 顺序编码制**著录（中文写作默认），英文写作下换成 **APA 第 7 版**或 **MLA 第 9 版**。期刊条目按标准成形——GB/T：

> 「此前只有一副骨架（类型标识恒为 `[J]`、卷期页缺失、APA / MLA 是半成品）」那一版是什么样、为什么改，见 [DECISIONS.md](./DECISIONS.md) D-09。

```
[1] 王玲玲, 戴会超, 王琼. 三峡船闸水力数值实验室的研制及应用[J]. 河海大学学报: 自然科学版, 2004, 32(1): 100-103.
[2] WANG L, LI H, ZHOU Q, et al. Title of the paper[J]. Journal Name, 2023, 32(1): 56-75.
```

- **著者**：姓前名后、姓全大写、名缩写后**不加**缩写点且多个首字母之间空格分隔、著者之间一律用 `,`（不用 `and` / `&` / `和`）。**≤3 人全部列出，>3 人只列前 3 位**，后接 `等` 或 `et al.`——选哪个按**该条文献的语言**，不看界面语言（`ZHANG Wei, LI Ming` 这类不含汉字的条目会正确得到 `et al.`）。机构著者（`World Health Organization`）刻意保持原形，不被全大写。
- **期刊形态与降级**：`刊名, 年, 卷(期): 起止页码.`，缺哪一项就省哪一项（`教育研究, 2023.` 仍是合法输出）。**无卷无期无页的老条目输出与改动前逐字节一致**——`test_db.py` 里那三条这样的用例一个字都没改，它们同时就是这条的回归线。页码里的 `p.` / `pp.` 前缀会去掉，`–` / `—` / `~` 统一成 `-`。
- **类型字母**：`[J]` 期刊、`[M]` 专著、`[D]` 学位论文、`[C]` 会议录、`[N]` 报纸……按抽取结果**如实印出**（此前一律印 `[J]`）。**v1.28 起 `[M]` / `[D]` / `[C]` / `[N]` 各有完整的著录模板**（下面单独一条），此前那一句「非期刊类型没有做完整著录模板」已经作废：旧说法是"那需要出版地、出版者、版本、学位授予单位，这些字段与录入界面本轮都没做"，而 v1.28 补了三列（出版地 / 版本项 / 报纸出版日期），出版者与学位授予单位与论文集名与报纸名则**复用已有的「来源」**——它本来就是这几样东西。`[J/OL]` / `[EB/OL]` **仍然不做**，它们还要 URL 与引用日期，那两个字段与录入界面仍没有：宁可如实少印，也不印一个没有 URL 的 `[J/OL]`（那比 `[J]` 更不合规）。
- **非期刊类型的著录形态（v1.28）**：专著 `作者. 题名[M]. 版本项. 出版地: 出版者, 年: 页码.`、学位论文 `作者. 题名[D]. 出版地: 学位授予单位, 年.`、会议论文 `作者. 题名[C]//论文集名. 出版地, 年: 页码.`（`//` 是 GB/T 区分"析出文献"的写法，句点落在论文集名之后）、报纸 `作者. 题名[N]. 报纸名, 出版日期.`。**触发条件是"本类型专属的那几列至少有一项非空"**——出版地 / 版本项 / 报纸出版日期上面都有对应的编辑框，**留空就逐字节退回原来的兜底形态**（存量条目与"模型没抽到新字段"的条目因此与改动前一个字符都不差）。报纸日期认 `2023-05-04` / `2023/5/4` / `2023年5月4日`，认不出就原样打印。**两处已知偏离如实记档**：报纸不印版次、会议论文不印论文集主要责任者。
- **白名单**：类型字母只能落在 `J M D C N R S P G Z` 内，**越界一律回落 `J`**。这个值会被直接印进参考文献文本，而它来自模型输出——不设白名单就等于让模型往正文里写任意字符。用户从编辑界面手填越界则**报 400**（手填是显式输入，不该被静默改成 `J`）。
- **抽错了能改**：文献列表每项有「编辑」，题名 / 作者 / 英译题名 / 年份 / 来源 / 卷 / 期 / 页码 / 出版地 / 版本项 / 报纸出版日期 / 类型十二个字段都能改（类型是下拉，选项由白名单派生，不是手写；英译题名只对 APA / MLA 有用、后三项只对 GB/T 7714 的非期刊类型有用，见下）。此前抽错只能删了重传，而重传会被**内容判重**挡回来——等于改不掉。改了题名之后文末列表那条立刻过期，界面按原有的引用一致性机制给出**「重排文末列表」**（零模型调用、正文一个字都不用动）。
- **英文文献此前更差，主因在抽取不在格式**：元数据全部由一次模型调用产出，而它此前只喂**第一页前 2000 字**（英文期刊首页是"大标题 + 长摘要 + 版权信息"，作者与刊名行常落在外面）、PDF 的**硬换行不合并**（作者列表跨行全靠模型自己接）、缺题名时还会印出中文占位（`（未命名文献）`）。现在取前两页、合并硬换行、上限放宽到 8000 字符，并在提示词里明确索取**卷 / 期 / 页码 / 类型**。
- **题名以 `?` / `!` 收尾时不再冒出双标点（v1.27）**：APA 的两条分支与 MLA 此前都**无条件**在题名后补一个句点，于是 `Is AI Creative?` 印成 `Is AI Creative?.`——这条路是 v1.26 才打开的（在那之前这两种格式还是"作者串原样印出"的半成品，没人走到过），所以它是新能力带出来的形状问题。判据收敛在**一处** `_terminated`（结尾已是 `.` / `?` / `!` 就原样返回），MLA 的终止符落在引号内；**GB/T 7714 分支刻意不共用它**——它是 `题名[J].`，方括号夹在题名与句点之间，任何收尾字符都不冲突，顺手"统一"就会改动中文这条路径。
- **APA / MLA 也是真身了（v1.26）**：这两种格式此前是"作者串原样印出"的半成品，现在按 APA 第 7 版与 MLA 第 9 版著录——姓名倒装（`Smith, J. K.` / `Smith, John K.`）、APA 末位著者前用 `&`、MLA 两位用 `, and `、三位以上 `, et al.`、**20 作者规则**（APA：≤20 位全列，21 位及以上列前 19 位 + `…` + 末位）、缺年份写 `(n.d.)`、`vol.` / `no.` / `pp.` 前缀、页码归一。中文文献写进英文论文时按 APA 7 §9.38 印成 `原题名 [English translation].`——英译题名在**上传解析时**就一并存下（**存量文献没有这个值**，APA/MLA 下退回"只用原题名"，要补只能重新上传）。
- **三种格式的姓名形态是不同的，不能共用一套**："这一条文献是不是中文"的判据（含不含汉字）三种格式共用一份，但**印出来的形态各是一套**：GB/T 是 `WANG L`（姓全大写、名缩写不带点），APA 是 `Wang, L.`，MLA 是 `Wang, Ling`。所以文献编辑界面对「作者」字段的提示必须**并列说清三种形态**——只写"选 GB/T 时会整理姓名、其余格式原样输出"在本轮之后就是假话（`test_citation_format.py` 里那条 `test_author_normalization_is_gb7714_only` 也随之改名：它的**前提**被本轮有意推翻了，不是重新基线）。
- **两处偏离标准是有意的**：① **保留数字编号与"正文首次引用顺序"**——标准的 APA/MLA 列表该是字母序且不编号，而正文角标 `[n]` 是生成时**烘死**在正文文本里的，只改列表形态等于让正文与列表对不上；② **斜体只在 `.docx` 里做**——APA 的刊名卷号、MLA 的容器名本该斜体，而三种导出里 md 与 txt 是纯文本、斜体**没有落点**，所以只有 Word 那一份做（做法见「导出格式」一节），**v1.28 起这一条从"哪一份都不做"收窄成"两份纯文本不做"**。①与"做著者-出版年制"一起留到**动正文角标**的那一轮。
- **格式选项按写作语言收敛**：中文写作下 GB/T 7714 / APA / MLA 三项都列出来、默认 GB/T 7714（选 APA/MLA 时给一句"这不是中文期刊常用格式"的提示，**不禁用、不拦阻**）；英文写作下**只有 APA / MLA**、默认 APA。界面下拉与后端拒绝用的是同一份判据，**直接调接口也一样**——英文论文 + GB/T 7714 会在写库之前被 400 拒绝，报错信息里同时给出格式的显示名与标识（只印标识则用户对不上自己刚选过的那一项，只印显示名则调接口的人不知道请求里该填什么）。
- **刻意不做**（这一轮之后仍缺的）：**著者-出版年制**（正文改 `(Wang, 2023)`、文末列表去编号并改字母序——正文角标烘死在文本里，与上面"保留编号"是同一条约束的两面；**它的性质是待办、不是取舍**——方案与代价见 PRD §10.2，v1.26 之后仍未到期的原因是"它改的是正文角标，而英文能力那一轮动的只是文末列表形态"）、**`[J/OL]` / `[EB/OL]`**（缺 URL 与引用日期这两个字段与录入界面）、**md / txt 里的斜体**（纯文本没有落点，是有意取舍）、以及**中文界面文案的英文化**（有意为之，见「写作语言」一节）。此前还列着"斜体"与"非期刊类型的完整著录模板"两条，**v1.28 已做掉**（分别是"只在 `.docx` 里做"和上面那条非期刊形态），故从这份清单里移出。

### 引用绑定与材料计划都以「章节标题」为 join key

引用绑定与材料融入计划都按章节标题挂到大纲上，因此失效条件一致：**章节标题变了，两者都作废**。系统在「确认大纲」时主动检查（不依赖用户自觉），并把作废结果回传前端提示。宁可让用户重做一次调度，也不允许模型拿着悬空引用去凭空编造——那会直接击穿「0 幻觉引用」。

### 修改上游设定：覆盖式作废 + 提交前告知

选题与设定（类型 / 目标字数 / 选题 / 写作思路）是全流程的最上游，大纲、正文、引用绑定、材料计划都由它派生。所以它可改，但**改动的代价必须在点击之前就知道**——否则就是把「静默写错」换成了「静默删稿」，而删稿不可撤销。

- **只有真改了才作废**：逐一比对 `选题 / 论文类型 / 写作语言 / 目标字数 / 写作思路` 五个字段。五者全等时（只是点了一下确认、或重提了同一份内容）**不动数据、也不改状态**。原实现无条件写 `status = 选题完成`，一次「路过点击」就能把已走到「大纲已确认」的项目打回上一步。
  - 写作思路按 `strip()` 后的值比对，且**只 strip、不折叠内部空白**（它是多行文本，段落结构有意义）。多行输入框里敲完一段顺手回车、末尾留一个换行是常态而不是边界——裸比会让一次「只是换行」的点击作废掉六项产物。
- **作废范围是覆盖式的**：大纲、正文、引用绑定、材料融入计划、参考文献快照、生成状态六项一并作废，状态退回「选题完成」。不保留、不静默降级——留着它们就是留着一份按旧选题写成的稿子挂在新选题下面。**正文整篇覆盖、不保留草稿**，所以提交前的提示会建议先到「预览导出」步复制或下载保存一份。
- **两处刻意不动**：**设计字段**只在**论文类型**变化时作废（字段名是数据的键，而字段名随类型走；只改选题时设计仍然成立）；**主题聚类**一律保留（它由文献本身决定，与选题无关）。
- **告知只在真有东西可失去时才弹**：空项目改选题是常态，每次都弹确认框只会训练用户闭眼点「确定」。有内容时才弹，且逐项列出失去什么（已生成的 N 节正文 / 大纲 / 引用绑定 / 材料融入计划）。
- **有活正在跑时不改**：后台任务进行中（大纲生成、文献解析、材料分析、聚类、设计提炼、引用调度）或正文正在生成时，改选题返回 **409** 并说明是哪一项在跑；项目不存在返回 **404**（原实现是 `UPDATE` 影响 0 行却返回 `null`，调用方以为成功了）。

### 引用一致性：正文、文末列表与文献库必须对得上

正文里的角标是**生成时烘死的字符串**，文末参考文献列表是按当次编号算出的**快照**——二者只在生成的那一刻彼此对齐。生成完之后再去删一篇文献、或重做一次调度，绑定与编号会变，而正文里那串 `[n]` 不会自己跟着变：`[3]` 与列表第 3 条就指向了不同的文献，"0 幻觉引用"当场失效。

系统**不猜测、也不静默改写你的正文**，只给三条出口：

- **看得见**：绑定与当前正文不一致时，界面挂一条**不可关闭**的告警条（服务端在每次读取项目时现算 `citations_stale`，与论文标题的 `display_title` 同型）。**故意不给关闭按钮**——它是"此刻仍然成立的事实"，不是某次操作的后果；把绑定改回原样，它自己就消失。
- **说得清、给一个相称的补救**（`refs_change`，"不一致"其实是**两种后果差一个量级**的情况，此前共用一句话、共用一条出路）：
  - **只有文末列表的排版变了**（列表格式 / 角标样式）→ 诊断报 `render`：编号与指向一一对应，角标指的还是原来那篇文献。出路是**「按当前设置重排文末列表」**——**零模型调用、正文一个字都不用动**。这条路的准入门槛就是安全性本身：只有 `render` 才放行，编号变过时重排会亲手做出"正文角标指着 A、列表第 3 条写着 B"这种静默错配，必须先被 400 拒。写下去的值与护栏比对用的是**同一个函数**，所以完成即一致、不是碰巧。（改的是角标样式时还有一条重排修不掉的残留，系统会如实说出来：**正文里的角标字形仍是生成时那一种**——角标在正文里，只有重写正文才会变。）
  - **编号或成员变了**（改绑定、删文献后重排、换归属）→ 诊断报 `numbering`：`[3]` 与列表第 3 条不再是同一篇文献，**只能重写正文**。出路是**「作废正文并重写」**：只清正文、文末列表基线与生成进度，**大纲 / 引用绑定 / 设计 / 材料计划 / 文献与材料一字不动**。它同时补上一个此前**完全不可达**的诉求——想重写一版正文（此前只能靠改选题绕路，代价是把四份下游产物一起作废）。
- **拦得住**：点「生成正文」时比对"已落盘的正文是按哪一版编号写的"与"现在这一版"，不一致就返回 **400** 并说明原因（文案按上面两类分版，直接告诉你去点哪个按钮）。检查放在**路由层、零写入**，界面上不会出现"启动了一下又失败"。**拒绝是非破坏性的**：旧正文本是自洽的完整一篇，不会被清掉。
- **补得进新文献**：绑定只在点「执行引用调度」的那一刻定格，而**上传新文献不会自动重排**——因此调度之后再传进来的文献**从未进入任何章节**，正文角标与文末列表里都没有它们（你以为传进去了，实际它在正文中不存在）。这一条与上面两条**并列而不同**：上面两条讲「正文 vs 编号」（补救＝重新生成正文），这条讲「文献 vs 绑定」（补救＝重新调度）；合成一句，用户会照着错的那条去修。判据是服务端每次读取项目时现算的 `unbound_documents`（**文献库里不在当前绑定里的篇数**，与 `citations_stale` 同型的非列字段，不加列、不加哨兵、不做迁移——打散算法会把当时库里的每一篇都绑出去，所以"调度完成的那一刻两个集合必然相等"，此后的差集只可能来自文献集合变动）。它**必须单独存在**：`citations_stale` 结构上看不见这件事——它按"绑定里的 doc_id × 当前文献库"重算文末列表、再与落盘快照比对，未进绑定的新文献对这份快照零影响，标志恒为假；尤其在"跳过引用调度 → 补上文献 → 续写"这条路上，落盘快照与重算结果都是空列表，`[] == []` 使它**永远为假**。界面据此把「执行引用调度」提为本步主按钮（「确认引用绑定」与前进按钮同时降为次级，**任何时刻卡片里恰好一个主按钮**），卡片里说明"有 N 篇文献还没有绑定到任何章节"；按「确认引用绑定」时弹一次告知后放行——**它只是把当前这份绑定盖章，不会把它们补进来**（照抄材料那句是错的：材料是丢下不管，绑定是盖章固化）。**没有叶子章节时一律不提示**（此时调度本身就返回空绑定，重排一次也修不好）。**提示只摆在补救所在的那一步**、不做成全局常驻条：`unbound_documents > 0` 在"刚传完文献、还没轮到调度"和"文献综述正在批量上传"时都为真，那是完全正常的中间态，一条琥珀色警告挂在每个步骤上只会变成用户学会无视的噪声。

两个容易踩的细节都处理了：基线（`references_json`）**只在真的写出正文时落**——每轮开头都写一遍，等于当场把"生成完之后改过引用设置"洗白；「**从未写过**」与「**写过但零引用**」必须区分——前者是历史数据、不可验证，后者是"跳过引用调度"的合法产物，混同会让"跳过引用 → 补文献 → 续写"这条路径静默漏判。

三个事实**回答三个不同的问题，不能合成一句**（合成一句，用户就会照着错的那条去修）：`citations_stale` 讲「正文 vs 编号」、`unbound_documents` 讲「文献 vs 绑定」、`refs_change` 讲「**到底哪一样变了、该用哪个补救**」。三者都是**每次读取项目时现算的非列字段**（不落库、不加列），并且走**同一组挂载点**（项目详情 + 调度/确认/跳过三个写接口，列表接口刻意不挂）。诊断与那句人话也**由服务端算一份**，前端只渲染——它有两个消费点（告警条与 400 文案），各拼一遍就是两份迟早漂移的实现（`display_title` 的五个消费点曾各写一遍兜底词，正是这个坑）。

还有一条**只记档、没有改**的既有行为：启动时的参考文献快照迁移会按项目*当前*设置就地重算排版，所以"只改了列表格式"这类不一致会随重启被静默修好——提示出不出现，取决于后端重启过没有。新的显式重排与它结果一致，只是**立刻且可见**。**v1.27 修掉了其中一个具体成因，这条记录本身仍然成立**：那次"只改了列表格式、重启后被静默修好"还有一条更隐蔽的分支——运行期写出的文末列表与启动重算用的**元数据字段清单不一致**（运行期少一项英译题名 `title_en`），于是一份绑定的告警条亮不亮，取决于后端**重启过没有**，而「重排文末列表」走的正是缺项的那一处、怎么按都修不好（同一段代码的注释自己就预言过这个症状）。清单现已逐项对齐，并有**一条挂在数据交接处的用例**盯着它：把**运行期产出的**快照写回库、再跑一次重算，改写数必须为 **0**（用旧形态的快照则是 1）。重算里那个绕开唯一解析点的默认值也一并删掉。**重算本身仍在启动时静默发生**，那条记录照旧。

已完成的稿子**允许**再改引用绑定（用户可能就是想补一篇文献进去）：不改状态、不退步骤，不一致交给告警条说明——**"上游被改过"这件事由告警条承载，而不是靠改状态**（把已完成的稿子退回上一步，只会让用户以为正文被撤销）。

这条判据**只算一个方向**，有意留下一处盲区：看不见"绑定里有一篇文献库里已不存在"（悬空 `doc_id` 只会来自手工构造的确认请求体，界面从不自己编绑定）。真要管应当管在**写入口**（丢弃或 400），而不是再加一个读取侧字段——那是另一件事，本轮没做。

### 论文标题：跟随研究核心方向 + 可随时改名

项目在界面上的名字**就是论文标题**，也是导出成品的一级标题与下载文件名（三种导出格式都一样）。取值按优先级：**用户改的名字 → 研究核心方向 → 「未命名论文」**（最后一个只是显示兜底，不落库）。

- **跟随规则**：提交选题时，只有当标题**还空着、或恰好等于上一次的选题**时才跟着改。你一旦手动改过名，之后再改选题就不会覆盖它——那是你刚说过的叫法，不该被一次选题调整悄悄抹掉。判据只用"现值 vs 上游值"表达，不新增"是否手动改过"的标记列。
- **清空即回到跟随**：改名时留空保存是**合法输入**，含义是"我不自己起名"而非"把名字删掉"——标题立刻回到当前选题，并从此重新跟随。
- **改名不受任何守卫**：它不写状态、不作废任何产物，所以连"正文正在生成中"也不拦（没有可失去的东西，就没有理由打断）。
- **推导只由服务端算一份**（`display_title`，随项目接口下发，与 `citations_stale` 同型的**算出来的非列字段**），前端只渲染。它负责五处：项目列表卡片、页头、删除确认弹窗、导出的一级标题、下载文件名——各写一遍 `|| '未命名论文'` 就是五份迟早漂移的实现（原先那五处里两处兜底词是「论文」、三处是「未命名论文」，导出文件名与界面显示的名字本就不是同一个）。它也挂在一个项目的**所有**返回值上（含新建与确认选题的响应），因为前端拿到响应就直接替换本地副本。
- **存量数据**：`projects.title` 这一列一直存在，但旧版本的**唯一**写入点是前端写死的一个常量，此后没有任何改名入口，所以历史项目全部显示「未命名论文」。启动时的一次性幂等迁移把它们换成各自的选题（没有选题可置的置为 NULL），**刻意不更新 `updated_at`**——项目列表按它倒序排列，动它会把这批项目整体跳到最前，而用户什么都没做。

### 写作思路：把「打算怎么论证」交给作者

选题步此前只有「确定研究核心方向」一个输入框，而**一个标题装不下"打算怎么论证"**：同一个选题下，"先辨析概念再论证互补"与"用面板数据检验替代关系"是两篇不同的论文。所以这一步多了一个自由文本框（**选填，2000 字以内**），写你自己已有的写作思路或论证思路。

- **它喂两处**：生成大纲时（第一遍声明的那句主线必须收敛到这段思路、不得另立一条，你点到的论证角度与主题偏向会落到节标题上），以及写每一节正文时（连同那句主线一起下发）。
- **你写的优先**：与模型的推断有出入时以你写下的为准。大纲页顶部显示的那句「核心研究问题」就是把你的思路收敛成的一句话——一眼能看出它是不是你的意思，不对就改思路重新生成。
- **顺带补了一个洞**：那句核心研究问题此前**只到大纲、从未进过正文提示词**——写每一节的模型看不到全篇主线，只能从节标题反推，而节标题本身是被模型改写过的一句话。现在它和你的思路一起逐节下发。
- **改了它等于改了选题**：与选题 / 类型 / 字数同一口径——真变了就覆盖式作废下游六项产物，并在提交前逐项告诉你将失去什么。只改了末尾一个换行**不算变**。
- **它与「研究材料」不是一条通道**：材料的分析前置条件是大纲已存在，所以材料**结构上永远进不了大纲**。把论证思路写进「研究材料」里，大纲会**无声地忽略它**——要影响大纲与全文主线，写在这个框里；要交数据、素材、调研笔记，才去「文献注入」步用「研究材料」。
- **不静默截断**：超过 2000 字会明确报错（告诉你已写多少字、上限多少），而不是悄悄截掉半段——作者的方案被吃掉一半而不知情，论文就会照着另一条线写下去。前端刻意**不加 `maxLength`、也不做计数器**，就是为了让这条错误真的能弹出来。

### 目标总字数：能整个删空，最少 1000 字

框里存的是你正在敲的那串字符（可以是空的），数字另存一份——所以能整个删空。**关键在它没有把数字本身改成字符串**：大纲步按「各节字数之和 = 目标总字数」判断能不能确认大纲，数字与字符串相比恒为假，确认大纲的按钮会永久禁用。
（此前它删不空，空串被落成 `0`，敲错一位就是十倍错值——改动经过见 [DECISIONS.md](./DECISIONS.md) D-25。）
- **大纲步那两个每节字数的输入框也走同一个读数入口（v1.27）**：它们此前自己写了 `parseInt(e.target.value, 10)`，而同一个文件里早有正确的 `wordsNumber`（注释还专门写着"`parseInt` 会把 `1e3` 读成 1"）——于是 `1e3` 被读成 **1**，那一节的字数预算当场错三个数量级。现在两处都走 `wordsNumber`，同时保留"删空 = 未分配"的语义（`0` 是一个合法值，两者必须区分）。这条约定用一句断言钉住：剥掉注释后的 `App.jsx` 里**不出现 `parseInt(`**。
- **最少 1000 字**：它是全篇总量，到「大纲与字数」步会按节分掉；低到一定量级以下"按节分"就没有意义了。输入框旁边常驻写着这个下限，后端另有一道同样的校验（前端若过期，也会被后端原样拒绝）。
- **不足时按「确认选题，进入下一步」会当场说明**（提示就在按钮上方，写着下限和你当前填的数），**而不是把按钮变灰**——一个点不动的蓝按钮等于什么都不说。「AI 推荐选题」在这时也会禁用并说明原因：推荐的"匹配度"是拿目标字数当基准评出来的。
- **上限没做**（如实说）：字数没有上限。

### 写作语言：中文 / 英文，它只管产出物

选题步新增一个「写作语言」选择，中文 / 英文两项。**它决定的是这篇论文里会印出来的那些字**——论文标题、摘要、关键词、大纲的章标题与节标题、每一节正文、文末参考文献的形态、以及导出的排版。

- **界面本身仍是中文**（有意为之）：类型名、工序名、按钮、提示语都不跟着变。理由是界面文案**不会变成论文里的一行字**——把它一起翻掉只会让中文用户在看不懂的英文按钮上找功能，而论文该是英文的那部分已经跟着语言走了。
- **字数口径跟着语言走**：中文按**字**计，英文按**词**计（空白分词，`[1]` 这样的话题角标也算一个词，与 Word 的"字数（words）"一致）。所以目标字数框旁边的单位会从中文的"字"变成英文的"words"——**不换单位的话，"目标 5000"会被当成 5000 个英文词填进去**，那是中文 7500 字左右的体量。这一条不是文字游戏：按字符计的英文正文会永远"字数不足"，于是反复重试扩写、最后落到占位文本，症状看上去像模型出了问题。
- **骨架是两套，形状必须一样**：七类论文的中文骨架合起来是 34 章 / 74 节，英文骨架是**平行并列的另一张表**、同样 34 章 / 74 节。测试里钉着一条不变式——逐类型比对，**英文骨架与中文骨架的章数、每章节数必须逐位相同**，漏翻一节会当场变红。（另一条专项护栏盯的是一个**静默**失效点：文献综述的主题聚类靠"章标题里含不含『研究主题脉络』"来定位那一章，英文骨架下这个中文子串匹配会**返回 0 且不报错**，于是合并检查被整段跳过、界面上一切正常——所以英文骨架另有一个等价的章名，并有一条"两种语言下这个计数必须同值"的回归。）
- **格式选项按语言收敛**：选了英文，参考文献格式的下拉里**只剩 APA / MLA**（默认 APA）——英文期刊不用 GB/T 7714。中文写作下三项都列出来、默认 GB/T 7714，选 APA / MLA 时会有一句提示说明这不是中文期刊常用格式，但**不禁用、不拦阻**（APA 在中文写作里是合法选择）。这条判据只有一份，界面下拉与后端拒绝用的是同一个数据源：**直接调接口也一样拦**，英文论文提交 GB/T 7714 会在写库之前被 400 拒绝，报错信息里同时给出格式的显示名与标识。
- **省去「写作语言」这个字段 = 不改这一项（v1.27）**：提交选题的接口语义是「字段缺席 = 不修改这一项」，**不是**「回落到默认的中文」。这条读法只给语言——它省去的默认值带破坏性：省略即中文会把一个英文项目掰回中文，并连带作废大纲 / 正文 / 引用绑定 / 材料融入计划 / 参考文献快照 / 主题聚类与生成状态，而调用方只是没发这一个键；其余四个字段（选题、类型、字数、写作思路）省去的默认值与库里的"没写过"本来就同义，不适用这条。
- **那句"这不是中文期刊常用格式"的说明也由后端给（v1.27）**：后端下发的说明表，**键集固定为全部三种格式**（不是该语言能选的那几种），所以英文下也拿得到 GB/T 7714 那一条——它唯一的用途正是解释这一项**为什么不在下拉列表里**。前端渲染的就是「被本语言排除掉的格式」的说明，不按语言自己判一遍、更不手写文案（手写的那一份与后端的表迟早对不上，一旦判错，给出的就是一句与列表不符的解释）。
- **「AI 推荐选题」按你在表单里选的语言走（v1.27）**：语言取请求里带的那个值优先，没带才回落到库里那份。此前它只读库里的 `writing_lang`，注释还写着"两者总是同源"——那句在**新建项目时是假话**：在选题表单里选了英文、还没确认项目就点「推荐」，库里仍是中文，于是发出去的是中文提示词、回来的也是中文选题方向。
- **改语言 = 改一个上游设定**：与改论文类型、改选题同一口径——已生成过产物时，提交前会弹确认框逐项列出将失去什么（大纲、正文、引用绑定、材料融入计划、参考文献快照，**外加主题聚类**：聚类产出的主题名会变成文献综述的节标题，是产物文字）。确认后按新语言重来。**中文改英文时若当前格式是 GB/T 7714，会在同一次保存里自动改成 APA**（上一个选择在新语言下不合法，直接替你收敛，不报错）；**英文改回中文时不动格式**（APA 在中文下合法，擅自改掉等于替你做了选择）。
- **一处存量代价（如实说）**：中文文献进英文论文时按 APA 7 §9.38 印成 `原题名 [English translation].`，那个英译题名在**上传解析文献时**就存下来了——**此前上传的文献没有这个值**，英文项目下会退回"只用原题名"。要补齐只能**重新上传**那几篇（本轮不做回填：没有源可译）。

### 回看不等于回退

步骤条上已走过的步骤都可点击回看，**回看这个动作本身不作废任何产物**。这一点需要显式保证，因为此前的表现恰好相反：点回前一步之后，只能靠「下一步」按钮一级一级走回后面，看起来就像后面的内容已经被撤销了——用户往往会顺手把已经生成好的内容重新生成一遍。

做法是可达范围取三者最大值：**服务端前沿**（状态机推到哪一步）、**本地只增不减的记忆**（本次会话走到过的最远步骤）、**当前下标**。本地记忆不能省：像「不注入文献，进入引用调度」这类跳过型操作不改服务端状态，只靠服务端前沿会让用户跳过之后回不去。只有一个例外是重新载入项目——那时记忆与前沿一起重置，避免把上一个项目的进度记到新项目上。

### 引用调度：按相关性归属 + 确定性兜底

把上传的文献归属到大纲章节，**按主题相关性**判断，而不是按上传顺序轮转：

- **一次模型判断**给出"哪篇文献属于哪一节 + 一句依据"。输入只有大纲的**叶子章节标题**与每篇文献的 `id/标题/作者/年份/来源/摘要`（摘要截断；超过 50 篇只发前 50 篇，并如实告诉模型还有多少篇没列出）。
- **白名单校验**：模型选中的标题必须**逐字命中大纲叶子**、`doc_id` 必须在文献库内、同一篇只取第一条——编出来的标题与文献一律丢弃。
- **四条承诺由代码保证，模型一条都不负责**：无遗漏、无同章重复、**每节都有引用**、页码确定（页码由代码按文献页序给出，模型看不到页内容）。补缺口由 `fill_gaps` 完成，它只补不推翻：模型说这篇属于第 3 节，就留在第 3 节。
- **为什么"无遗漏"不能交给模型**：这一步**没有绑定编辑器**——模型判定"这篇与本大纲无关"之后，界面上没有任何地方能把文献加回来，那篇文献就再也用不上了。保留无遗漏，等于不让模型拥有一个**用户无法挽回**的决定权。
- **兜底 = 按上传顺序均匀铺开**（原有的 `uniform_distribute`，一行未改）：模型不可用 / 超时（120 秒）/ 输出不可解析 / 一条有效条目都没有时，整条流程照常跑完，只是归属由兜底给出。响应里的 `method`（`relevance` / `uniform`）如实区分两者，界面在兜底时提示**请人工核对**——走的是哪条路只有这一句话能告诉用户。
- **不做后台任务化，但要登记**：这次调用是一次小调用、结果被同一步立即消费、失败必然退回确定性兜底，用户永远拿到一份可确认的绑定并知道是哪一种，所以保持同步路由（按钮的 loading + 120 秒上限已够）——它不需要"进度落库 + 重启可恢复"那套机器。**但那段等待仍然占用这个项目**，所以它登记进 `tasks._TASKS`（键 `citations:<id>`，与其余五个同一张表）：调度期间其它入口一律 409，且写库用的是**等回来之后重取**的项目行。这一条不是洁癖——漏登记时的现场是"调度收尾用等待前的快照把别人刚写下的状态顶回去"，而这段时间里别的入口有十来个（改选题、点火生成、删文献、重新生成大纲、重置正文……）。**（v1.29 追加）这一条里"按钮的 `loading` 已够"半句已经作废**：这 120 秒里界面上现在有一条进度条（不确定条），真实阶段写进**同一个共享进度槽**（`kind = "citations"`，四个阶段：准备 → 逐篇判断 → 终态 / 错误），`kind` 也第一次进得了轮询结果。**"不做后台任务化"这个决定本身没有翻**——路由仍是同步的，那 120 秒仍然由**发起的那一侧**用本地判据渲染、由 **HTTP 响应**收尾（关掉页面＝放弃这一趟，与其余步骤一致）；**"它不需要重启可恢复"照旧成立**（同步动作没有可恢复的中间态，槽里万一留下的残留由 `reset_stale_tasks` 收掉）。**代价如实记**：同一个"在飞"从此有**两处**记录（`tasks._TASKS` 与进度槽），两者可能不一致（进程被杀在写槽中间），而没有任何读取方同时看两者 ⇒ 退化回旧盲区（条在转、按钮亮的、点下去才被 409 拒）。
- 归属列表在本步是**只读展示**（章节 → 文献 → 页码 → 依据），让确认点②看得见自己在确认什么；**不做可编辑的绑定编辑器**（能改是另一件事）。
- **不做每章引用篇数上限**、也不做"模型判定这篇不引用"的过滤模式：数量问题的正当出口是如实说明"你传的每一篇都会进正文"，而不是让用户面对一个只能靠重排、而重排给出同样答案的死角。

### 两次人工确认点

1. **大纲确认**：调整大纲结构与字数预算，校验总和 = 目标字数
2. **引用绑定确认**：查看并微调章节文献绑定关系

两次确认均为必选、显式、可追溯。唯一例外是确认点②可由用户**显式跳过**（七类均可，见上文；文献综述零文献时除外）——跳过同样是一个显式动作，不是"未确认也能过"。

**两道确认点在后端各有一道闸门**（不是只靠界面按钮置灰，见"关键设计"末两条）：

- **确认点①**（`/outline/confirm`）：状态白名单（`outline_pending` / `outline_confirmed` / `resources_loading` / `citation_pending` / `citation_confirmed` / `completed` / `exported`）+ 两套忙闲登记都查 + 两处都存在性检查。它同时是**状态倒退**的入口，所以 `generating` 明确不在白名单里。**生成大纲也一样**：正文生成中点「生成大纲」返回 409 —— 从前这条入口只查了通用任务那一套，放行的结局是大纲收尾把 `generating` 顶成 `outline_pending`，界面跳回大纲而生成任务仍在写正文。
- **确认点②**（`/citations/{schedule,confirm,skip}`）：同一道闸，见 `_require_citation_editable`。

设计录入**不是**确认点：它排在大纲之前，是确认点①的**输入**，所以系统不在缺设计时设闸门，只给后果明确的告警。主题聚类确认同样**不是**确认点，它是文献综述在确认点①之前的一道产物确认：不设硬闸（未确认仍可生成大纲，只给告警），但确实有一份可追溯的确认记录（`confirmed_at`）与一个下游动作（建议重新生成大纲）。聚类变更**不自动作废既有大纲**——已确认过的大纲属于用户，改它要由用户点头。

### 「文献注入」步：主按钮永远是你现在该点的那一个

这一步是全流程**唯一有两条资源线**的步骤（轨一文献、轨二作者材料），两条线各有一个"现在该点了"的动作。此前它是**唯一**把前进按钮排在卡片中部的步骤，而蓝按钮钉死在前进上——上传完作者材料的人，眼睛落在一个蓝色按钮上，点一下就**静默跳过材料**，材料既不进正文、界面上也没有任何提示。现在：

- **前进按钮排到卡片末尾**（与其余各步一致），不再夹在两条资源线中间。
- **主按钮随状态转移，同一时刻只有一个**：由**一处**判定驱动（有材料 + 还没有融入计划 + 分析未在跑 → 「分析材料如何融入正文」为主按钮），两个按钮各按它取样式，界面上不会出现两个主按钮或一个都没有。
- **未分析就前进，给一次告知**：确认框写明有 N 份材料不会写进正文，取消则留在本步。**不做硬闸**——材料是作者自己的一手内容、不是流程的必要条件，硬拦会把只想用文献的用户堵死；与"设计未填""未确认聚类"同一把尺子：**告知后果，然后放行**。材料为空或已分析时静默通过（不该弹的时候弹，只会训练用户闭眼点确定）。
- **分析进行中前进按钮禁用**：不是防错，而是别让用户在结果出来之前走掉、从而错过"这份材料没写进正文"这件事。
- **判定必须排除文献综述**：它的材料集合**可能非空**（先按别的类型建项目、加了材料、再把类型改成文献综述；改类型只作废设计字段、不动材料），而它又不渲染材料面板——照搬判定会得到一张一个主按钮都没有的卡片。
- **越过这一步之后仍会说一句**：材料集合的每一次变动（上传 / 粘贴 / 删除）都会立刻作废融入计划，所以"有材料、没计划"这件事**同时下发到两处**——本步（主按钮迁移 + 前进时的告知）和**引用调度步**（卡片里说明"有 N 份研究材料还没有分析"）。后者的补救动作不在那一页，所以措辞必须写明**地点与按钮名**：回到「文献注入」步点「分析材料如何融入正文」，而不是没有地址的"回上一步"；也要说清在那一页重排引用对材料毫无作用。两处消费的是**同一份判定**（前端在 App 里只算一次再往下传，各算一遍就会各漂一次——何况引用调度步连任务状态都收不到，自己根本算不了）。
- **抽错了可以就地改**：文献列表每项右侧的「编辑」与「删除」竖排（两个小按钮横着放会把长题名挤成两行）。编辑框能改题名 / 作者 / 年份 / 来源 / 卷 / 期 / 页码 / 类型字母，**保存失败的原因显示在框里**，不走页面顶部那条横幅——横幅在模态遮罩（`z-index: 1000`）后面，那正是"失败原因被吃掉"的形状，与 v1.21 修掉的那一类同源。

### 「大纲生成」步：两个出口，主按钮只亮在前沿的那一个

这一步的卡片上并排着**前后两个阶段的出口**：文献综述多一个「确认主题聚类」，全类型都有「生成大纲 / 确认大纲（人工确认点①）」。此前「确认主题聚类」是**无条件的主按钮**（确认之后文案变成「✓ 更新确认的主题聚类」，颜色还是蓝的），于是综述的大纲页**同时亮着两个蓝按钮**——而这两个动作的后果差一个量级：聚类确认只是给当前这组簇盖章（非破坏性），大纲确认会**作废引用绑定与材料计划**并把流程推进一步。用户没法从界面上判断谁在前谁在后。

- **一处判据决定谁蓝**：前端只算一个布尔（`clustersNeedConfirm` = 本步是文献综述 && 这个项目有文献 && 已有聚类 && 聚类还没被确认），三个按钮各按它取自己的样式。**三段互斥且穷尽**——有待确认的聚类 → 聚类确认蓝；否则大纲还没生成 → 「生成大纲」蓝；否则 → 「确认大纲」蓝。因此**任何时刻恰好一个主按钮**，顺带补上了此前"刚建项目、还没生成大纲"时一个蓝按钮都没有的状态。
- **判据只看已存的事实**（有没有文献、有没有大纲、聚类确没确认），**不猜你下一步想做什么**——"猜下一步"没有可依据的东西，而这三件事服务端都知道。
- **"不设硬闸"和"谁是蓝的"是两件事**：未确认的聚类照样能直接生成大纲（只给告警），这一版收紧的只是**哪一个是蓝的**，不是"能不能往下走"。
- **一处如实说明**：聚类确认之后又手改簇标题，本步仍会显示"已确认"（改标题不作废确认）；而下次重新生成聚类会把确认记录清空、聚类确认重新变回主按钮——那是对的，新的一簇你还没看过。

- **两遍提示词都要宣告输出语言（v1.27）**：第二遍虽然不动结构，但它产出**复核后的节标题**，而节标题会原样印进论文——只在第一遍宣告，被这一遍改写过的标题就会退回中文。补上的那个占位符紧贴在文献块之后、**不加分隔符**：它在中文下返回空串，因此中文提示词**逐字节不变**（另起一行会多出一个尾部换行）。

### 界面上不猜原因

**拿一个数字去指认原因，比不说原因更坏**——你会拿它去解释自己的项目，并按一条假前提去选动作。所以卡片上的横幅一律**并列穷举**："会落到这里的情形"逐条说出来，而且**每一句在每一种情形下都成立**，补救动作**无条件给出**（"不猜原因"不等于"什么都不说"，横幅的意义正是指向那个该点的按钮）。

引用调度步那条琥珀横幅此前写着「绑定是在上一次调度时定下的，此后加进来的文献不在其中」——而**从没调度过、跳过过引用**的项目根本没有"上一次调度"，跳过引用之后再补传文献这条路上两句都是假的，用户容易以为之前那份绑定丢了。现在与同卡片里材料那条对齐：「没调度过、跳过过引用、调度之后又增删过文献或改过章节标题，都会落到这里」，补救动作仍然照给（点「执行引用调度」重排一次）。

### 界面兜底：两层 error boundary

两层各管一件事（为什么需要这两层，见 [DECISIONS.md](./DECISIONS.md) D-21）：

- **外层**（`main.jsx` 包住整个 `<App />`）接渲染期与生命周期里的异常——应用不会再整个消失。
- **内层**（内容区外面再包一层）保住顶栏、项目列表与步骤条：出错的是**内容**那一片，用户**能切走、能重试**，而不是连左侧项目列表都点不到。
- **复位判据只有一处**：内层按项目 id 做 key，**换一个项目就自动复位**。否则一次异常之后切换项目仍停在错误卡片上，看起来像"这软件坏了"——而它其实只是上一张卡片没被重新挂载。

卡片上的话照本项目口径写：一句事实（"这一部分没能显示出来"）、**并列穷举**可能的情形（项目数据不完整 / 浏览器渲染出错 / 版本不匹配）、补救**无条件给出**（「重试」+「复制错误详情」——用户拿不到控制台，那是他把信息交出来的唯一通道）、出路**写明地点与按钮名**（"左侧项目列表里换一个项目"）。

两条约定断言盯住"它还挂着"（外层、内层各一条）外加一条"全树只有一处实现"，并且每条都用**变异探针**验过：把 boundary 摘掉，断言必须当场变红——否则就只是"断言了一段源码文本"的假绿。

### 分段生成与字数校准

- 按章节逐段生成，自动继承上文上下文（保持逻辑连贯）
- 每段生成后校验字数，偏差 > 5% 时自动重试/扩充/精简。**「字数」按写作语言分别计**：中文按字符（不计空白），英文按词（空白分词，`[1]` 这样的角标也算一个词，与 Word 的"字数（words）"一致）。这是**唯一**一处字数分发点，扩写/精简提示词与占位文本的填充都从它取值——英文若沿用字符口径，正文会永远"字数不足"，一路重试到占位文本，而症状看上去像模型出了问题
- 该节绑定的文献片段、该节归属的作者材料与全篇的设计字段一并进入上下文，但用途分列：文献用于转述 + 角标，材料用于融入、不加角标，设计是作者已确定的已知条件
- **正文提示词携带选题、类型名与该类型的写法要求**（`writing_note`）：只给"节标题 + 字数"，七类论文的正文写出来彼此没有区别。写法要求与章节结构说明同源同表（`TYPE_CONFIG`），改一处即两处生效。三者缺失时（老项目数据不全）以「（未指定）」占位，不让提示词出现空洞
- **全篇主线与作者写作思路也逐节下发**：大纲第一遍声明的**核心研究问题**与作者写下的**写作思路**一并进入每一节的提示词，并写明作者原文**优先于模型自己的推断、也优先于那句核心研究问题**。这两条此前**一条都到不了正文**——写每一节的模型看不到全篇主线，只能从节标题反推，而节标题本身是被模型改写过的一句话。两者都没值时整块渲染为空串，提示词与加此功能前逐字节一致
- 该节没有绑定文献时自动切换为**无引用规则**（不出现角标、不提参考文献、不编造文献观点），无需用户勾选
- **失败不静默**：推理模型偶发地把输出额度全耗在思考上、正文一字未吐（`finish=length` 且内容为空）。此时保留此前重试已取得的可用稿，而不是用空返回覆盖它；三次都没拿到正文才退占位文本，并在该节标 `fallback: true` —— 占位文本不进润色（否则会被改写成读起来像正文的句子）、不进下一节的上下文，措辞也区分「未配置 LLM」与「配了但没返回」
- **润色不得动引用角标，这条有代码级核对**：只靠提示词要求"保持角标不变"拦不住改标记，所以在润色返回后**逐个核对这一节的角标集合**（按**多重集**比较，允许同一节内调换次序）。掉号、改号、凭空多号、换样式（方括号 ↔ 上标）一律不通过，不通过就交回**未润色**的原文，并如实标明这一节没有被润色过。角标错位属于"引用指向了别的文献"，与上面的引用一致性是同一类问题，不能靠运气
- **正文写完之后，这张卡片上的主按钮是「查看导出结果 →」（v1.29）**：此前它在正文已完整生成时仍然印着「开始分段生成」，而那个按钮点下去后端会一路走完循环、发现一节都不用写，**只把 `status` 原样写回 `completed`（项目已经导出过时还会把 `exported` 顶回 `completed`）**——不报错、也不改变任何东西，一次纯空转；而真正该做的「重写正文」就并排在旁边。现在这一格按四段判：引用设置改过（`render` / `numbering`）时让给那两个补救动作，**没有诊断且正文已完整落库**时站「查看导出结果 →」（这才是这个状态下该点的那一个：前进，不是重做一遍），其余才是生成按钮；「重写正文」在任何情况下都还在。**"已完整落库"不按"节数够了"判**——`error` / `interrupted` 是既有的两种「可续写」终态，那时点一次「继续生成」正好把状态修回来，按节数判会把这两种状态也跳成"已写完"；「生成中」同样不算（否则蓝按钮会在写到一半时跳成「查看导出结果」）

### 导出：一个按钮带出三种格式

「预览导出」步的**「导出全文」**按钮是一个下拉菜单，三种格式任选（按钮文案 2026-09-18 由「导出」改来：导出的确实是全文，这一页上却还显示着「全文总计 N 字」这类局部信息）：

| 格式 | 内容与排版 | 实现 |
| --- | --- | --- |
| **Word（.docx）** | 标题居中加粗 16 磅、章节标题加粗 14 磅、正文 12 磅宋体、首行缩进 2 字符、1.5 倍行距、A4 与论文常用页边距；角标与文末参考文献列表照原样带入。**英文项目另换一套排版**（见下） | 手写 OOXML + 不压缩 zip（`exporters.js`），**不引任何库** |
| 纯文本（.txt） | 同样的顺序与内容，没有层级标记；换行用 CRLF（这份文件的主要去处是记事本与 Word） | 纯字符串拼接 |
| Markdown（.md） | 一级标题 + 各节二级标题 + 文末参考文献列表，与改动前的导出**逐字一致** | 纯字符串拼接 |

- **三种格式共用同一份「导出文档」形状**（标题、章节、参考文献在 `ExportStep` 里只拼一次），格式表只有 `exporters.js` 里的 `EXPORT_FORMATS` 一处——菜单项、扩展名、MIME 都从它来。各格式自己再拼一遍标题与列表，就是三份迟早漂移的实现。
- **预览区那句文末标题与三种导出走同一个函数（v1.27）**：「参考文献」还是 `References` 只在 `exporters.js` 的 `referencesHeading` 里判一次，预览与导出都读它。少一个导入**不是"退回中文"**——是渲染期的 `ReferenceError`（**v1.28 之前** `frontend/src` 全树没有 error boundary，整个 root 卸载、界面变成一片空白；**v1.28 起有了兜底**，见「界面兜底」一节——内容区被自己的 boundary 包住，用户看到一张说明卡片而不是空白窗口，且换项目即复位），而触发条件是"已生成正文且有文献"，也就是正常走完一轮的常态。因此这条约定断言落在**使用处**（这段代码用到了它，**且本文件的 import 行里有它**）：只断言"导出模块里有这个名字"是拦不住白屏的。**兜底不是躺平的理由**——它是给用户看的，断言是给下一个人看的。
- **Word 不用第三方库、也不走「HTML 改名叫 `.doc`」**：后者看着最省事，但新版 Word 会弹「文件格式与扩展名不匹配」。`exporters.js` 里手写 CRC32 与两处 zip 头部（store 不压缩），`document.xml` 的子元素顺序照 OOXML schema 写（`rFonts→b→i→sz`、`spacing→ind→jc`），Word 与 WPS 都能直接打开。**子元素顺序是 schema 约束、不是风格问题**（v1.28 加斜体时踩到的正是这一条）：`<w:i/>` 必须插在 `<w:b/>` 之后、`<w:sz` 之前，**追加到 `rPr` 末尾**的话 XML 仍然是良构的、`zipfile` 也检查不出问题，只有 Word 打开时才作废。
- **文末列表的斜体只有 `.docx` 做（v1.28）**：APA 第 7 版的刊名与卷号（含中间那个逗号）斜体、MLA 第 9 版只斜容器名，GB/T 7714 全正体。**哪几段该斜是格式标准的事，所以判断只有一处**——后端 `citation_format.py`，而且它是**同一份渲染器的结构化形式**：`formatted`（那条印出来、存进库、被所有一致性判断比对的字符串）**就是**这些片段文本拼起来的，因此加斜体这件事把既有的 6 条逐字节哨兵、引用一致性比对、启动迁移全部**原样保住**。片段**不落库**、只在组装响应时现算，随 `GET /projects/{id}` 与生成进度这两条路径下发；前端的 `doc.references` 仍是字符串数组（三种格式共用一份形状），拿不到片段时**逐条**退回整条正体，一条都不抛。md 与 txt 完全不读它——纯文本里斜体没有落点。
- **英文项目的 Word 换一套排版**（v1.26）：Times New Roman 12 磅（西文与东亚字体都换，不留一个宋体残留）、**双倍行距**、**段首不缩进**、四边各 1 英寸页边距，文末那一节叫 `References`（屏幕上与 `.md` / `.txt` 里一并跟着变）。这是英文论文投稿的常见要求——不换的话，一份英文稿上挂着中文论文的行距与首行缩进，排版上先就不像英文论文。
- **中文侧一个字节都没动**：`buildDocx` / `buildMarkdown` / `buildTxt` 的语言参数**追加在末尾且默认 `zh`**，现有调用与既有断言因此逐字节不变。这一点有两条独立的证据：一条是拿**已交付的 `release4` 打包产物**（这一轮之前烘好的 `index-*.js`）当外部基准，逐个确认当前中文排版用到的字面量它里面全都有、而英文独有的那几处它里面一处都没有；另一条是生成真实的 `.docx`，**换 Python 标准库 `zipfile` + `xml.etree` 当外部程序读**（`zipfile` 会校验每条记录的 CRC32）——node:test 里读 zip 的那段代码是本项目自己写的，自己的读法证明不了自己的写法。
- **文件名清洗三种格式一视同仁**：仍是同一套 Windows 非法字符替换与空值回退，只是扩展名随格式变。
- **预览与成品逐条一致**：文末列表在屏幕上此前是 `1. [1] 王玲玲. …` 这个样子——列表的字符串自带 `[n]`，而承载它的 `<ol>` 又叠了一层默认编号，导出文件里却没有这一层。现在关掉了 `<ol>` 的标记，屏幕上与导出文件里长得一样。
- 导出**全在前端**：内容在浏览器里已经有了，三种格式都在 `exporters.js` 里拼，**服务端一个字节都不参与**。代价是它进不了 pytest，所以 `exporters.js` 刻意不含 React——可以直接用 Node 跑起来做真实校验（zip 的 CRC 与 XML 解析 + 让 Word 真的打开一次）。
- **下载即回执**：每下载一次，前端顺手调一次 `POST /api/projects/{id}/export`，把项目从「生成完成」记成**「已导出」**——这是那个终态**唯一的写入点**（它此前被定义过、被读过，但全仓没有一处写它）。**下载与回执是两件事**：文件此刻已经在你的下载目录里了，回执失败只在提示条上说「文件已导出，但这次的导出没有记入项目状态（原因）」，**绝不写成「导出失败」**——那会让人以为文件是坏的、转头再导一遍。回执是幂等的，同一份稿子导两次（哪怕换一种格式）都成功。有任务在飞时导出按钮禁用并写明原因：不是拦住你，而是不让你点一个必然被拒的按钮。

### 长耗时操作一律走后台任务

大纲生成、文献解析、主题聚类、材料融入分析、设计提炼都是秒到分钟级的操作，统一由 `tasks.py` 登记为后台任务并落库进度，前端轮询 `/task/progress`：

- 同一列状态的任务互斥，重复触发返回 409
- 进度分两类：知道总量的（文献解析 k/N）给确定进度条，无法预知的（两遍 LLM）给不确定动画条 —— 不编造百分比
- **引用调度是这条纪律的唯一例外，而它现在也有进度条（v1.29）**：它只有**一次**模型调用（120 秒上限）、结果被同一步立即消费、失败必然退回确定性兜底，所以**没有做成后台任务**（路由同步等它结束）。此前它因此**不落进度**，那一格只有按钮变灰、最长 120 秒一个字都不给；现在把真实阶段写进**既有的**那个共享进度槽（`kind = "citations"`：准备 → 逐篇判断 → 终态 / 错误），界面在那 120 秒里显示一条**不确定条**（`done` / `total` 全程为 `None`——一次模型调用给不出百分比，编一个不如不给）。**两端各有各的真相、因此不需要 request-id**：发起的那一侧由**本地**在飞判据渲染（同步请求没有可轮询的服务端状态；这条本地判据记的是**哪个项目**，否则切到别的项目会看到一条属于别人的进度条），另一侧（另一个标签页 / 切走再切回 / 刷新）由共享槽种子 + 轮询驱动。轮询看到终态时**必须回填绑定**——少了它，"切走再切回"会拿着一份过期绑定去盖章，下一个点「确认引用绑定」就把刚跑完的调度结果顶回去；这一个调用还有**独享的 150 秒客户端超时**（没有它，一条死掉的 TCP 路径会让进度条永远转，那比没有进度条更假）。**关掉页面＝放弃这一趟**，与其它步骤一致，这是有意的边界、不是遗留缺陷。顺带一提：`kind` 进了轮询结果之后，"这个项目上有没有别的写操作在飞"在那 120 秒里就为真 ⇒ 别处的按钮是**灰的**，"按钮亮着、点了才被 409 拒"那条盲区随之关闭；而**"同一个在飞有两处记录"是这一版的代价**（登记表与进度槽，进程被杀在两次写入之间时可能不一致）——已如实记档
- **刷新页面进度不丢**，服务重启后僵死任务被标记为 `interrupted` 而非一直转圈；这个中断**在界面上如实说明原因并可重新发起**，包括刷新页面后才发现的那个（它是从项目快照里读出来的，不经过轮询），不会静默消失
- **进度槽只有一个**：界面上的任务进度是共享的一个槽，任务进行中会写它的入口一律让位（「AI 推荐选题」按钮置灰并说明原因），不覆盖正在跑的任务进度
- **失败如实呈现**：部分失败逐条列出「文件名（原因）」；**全部失败按失败报，不显示成「完成」**——一篇都没进库却显示解析完成，用户会以为文献已经在库里。**「读到一部分」是第三种结果，不是成功也不是失败**：一页坏掉不再被静默吞掉（此前一页留空、其余照常，调用方拿不到任何痕迹，"10 页里 3 页失败"与"完全成功"长得一模一样，缺的页要到引用调度那步才露马脚），解析层逐页标出失败、记一条**带页码与异常类型**的日志，任务里多出第三类上报 `partial`（"N 篇有页面未提取到"，前端逐条列「文件名（第 2、5 页文本提取失败）」）——能读的页照常入库、不计入失败，但绝不说成完全成功。**"整篇没文本"也要分清是哪一种**：每一页都抛异常 → "每一页的文本提取都失败"（文件坏了，重传或换一份）；每页都成功但都是空 → "未提取到文本（可能为扫描版）"（得自己去找带文本层的版本）。用错原因会把用户引到错误的动作上。**空页不是坏页**（章节之间的隔页文本本来就是空串），把它记成失败会让每一份带隔页的文献都报一条**假警告**，而假警告会让人学会忽略真警告
- **轮询自己会恢复**：进度轮询一次请求失败**不等于**这个任务永久失联（那会表现为进度条一直转、按钮一直禁用，只能刷新页面自救，而后端其实还在正常推进）。失败后重新排下一次轮询并按**指数退避**放长间隔（封顶 30 秒），累计失败次数写进提示语，恢复时只撤掉自己那一条错误。**刻意不做"失败 N 次就放弃"**——那会重新造出"永久失联"这件事
- **两套忙闲登记都要查**：通用后台任务与正文生成各有一套在跑登记，而它们**都会写项目状态**。所以任何"要不要拦"的判断（上传文献、启动生成、删除项目、改上游设定）都两套都查——只查一套的后果是：一个在飞的任务在收尾时把上游刚写下的状态顶掉，界面显示的是任务进度、库里是另一回事
- **有等待就必须登记，哪怕它不落进度**：引用调度的相关性判断是同一步里的同步等待（120 秒上限、没有进度可言、不写 `task_state_json`），但它同样占用项目——登记进同一张表（`citations:<id>`）之后，其余十来个入口一行都不用改就都看得见它。漏登记的后果与上面那条同型：调度收尾时会用等待**之前**取的项目快照写状态，把期间别人刚写下的东西顶回去。**（v1.29 追加）"不落进度"这半句已经不是事实**：执行引用调度那 120 秒里的真实阶段现在写进**同一个共享进度槽**（登记表仍是唯一那张、其余入口仍是一行都不用改），于是界面上第一次有进度条、`kind` 也第一次出现在轮询结果里。**而"有等待就必须登记"这条判据一个字没动**——它与"有没有进度条"本来就是两件事，将来若有别的同步等待仍不落进度，它照样要登记
- **守卫不能只在前端**：写上游状态的入口一律做**状态白名单**校验，而不是只检查"某个产物字段存不存在"——下游的产物在，恰恰不能说明上游的确认点已经过
- **界面上的忙闲判据对着后端那道闸**：每个会写后端状态的按钮，禁用判据都必须落在"**这个项目上有没有别的写操作在飞**"（两套登记都算）上，而不是"我自己这一类任务在不在跑"——按自己那一类判，稳定地做出**灯亮着、点下去必被拒**。各任务自己的 running 标记（大纲 / 解析 / 分析材料 / 设计提炼 / 聚类）此后只留给**它自己那一条进度条**。**一处如实记档的盲区**：引用调度的登记键前端看不见（它不写 `task_state_json`、界面上没有进度条、`kind` 永远不会出现在轮询结果里），所以它那 120 秒里按钮仍可能是亮的、点下去会拿到 409——这条盲区不靠再加一个字段去消（等于为一件事多造一处真相），靠下一条兜住。**另一头的边界同样写清楚**：`/materials/files`、`/materials/text`、删材料、保存设计这几处后端**本来就无闸**，它们的按钮不放宽也不收紧。**（v1.29 追加）上面那条"如实记档的盲区"已经关掉**：引用调度的阶段进了共享进度槽、`kind` 进了轮询结果，"这个项目上有没有别的写操作在飞"在那 120 秒里于是为真 ⇒ 按钮是**灰的**，而不是"点了才被 409 拒"——**"不加一个字段"这条没有被破**（用的是**既有的**那个槽，判据也一个字没动）。**"那句 409 的原因要能到用户眼前"仍然保留**：它挡的是别的来源（两个客户端之间、脚本、以及"同一个在飞有两处记录"那条窄缝）
- **失败原因不许在客户端被吃掉**：后端所有非 2xx 都带 `{detail: "中文原因"}`（400 的校验、404 的不存在、409 的「正文正在生成中」都走这条路），**那句 detail 是唯一能说明白"为什么失败"的东西**。上传文献与上传材料两个入口此前把整个响应体丢掉、各抛一句写死的「上传失败」/「材料上传失败」——于是"正文正在生成中，现在不能改文献"被显示成一句等于没说、还容易让人以为文件坏了的话。现在三处共用同一个取 `detail` 的函数（取不到才退回通用文案），上传失败后文件输入框一并清空（否则想改个文件重试时，选同一个文件不会有任何反应）
- 材料文本提取是纯本地操作，不占用后台任务

## 学术伦理声明

本系统定位为「辅助写作」而非「代写」。所有引用可溯源，杜绝 AI 虚构文献。生成内容需用户进行查重与人工复核。

作者自有材料只融入正文、**不充当引用来源**（不加角标、不进参考文献列表），避免把自己的数据伪装成文献证据。材料融入分析会如实指出证据缺口——例如只有描述统计与相关系数、不足以支撑中介效应检验，或访谈样本量小、只能作解释性佐证——并标明哪些节需作者补齐数据后方可成文。

**不得编造分析内容**：分析类章节只能依据作者已给出的设计字段展开（实证的数据源/假设/模型/结果；质性的对象/方法/编码/主题；工程的需求/架构/实现/测试；理论的假设/符号/推导/结论；技术方案的选型/参数/实测）。用户未填设计时，系统须**明确告知后果**后再生成，不得为了"跑通流程"而在用户不知情的情况下让模型把分析章节编满。

**类型不得串味**：每类的骨架与结构说明逐类固化，质性研究不得出现假设检验/回归/显著性，理论推导不得出现问卷/样本/描述性统计，工程设计不得出现实证分析，文献综述不得出现研究设计。判定标准是产出的章节标题里不出现该类被禁的章节用语。
